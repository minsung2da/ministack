# Phase 1 — UI Design Contract

> Visual and interaction contract for the App Shell & Navigation phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Key constraint:** This project uses **Cloudscape Design System v3** (AWS's open-source console design system) as the complete design system. Cloudscape supersedes shadcn — it ships its own design tokens, components, typography, color, and spacing. shadcn is explicitly rejected in STACK.md ("Cloudscape provides all styling. Adding Tailwind would fight the design system"). All values below are pulled from `@cloudscape-design/design-tokens` v3 (the canonical source) and must be referenced via the design-tokens package, never hardcoded.

## Layout Skeleton

The Phase 1 shell renders three regions, all provided by Cloudscape `AppLayout` (with `TopNavigation` mounted above it):

```
┌─────────────────────────────────────────────────────────────┐
│  TopNavigation                                              │  ← 56px fixed (Cloudscape default)
│  [MiniStack] [Service search ▾]              [region][⚙]    │
├──────────────┬──────────────────────────────────────────────┤
│              │  BreadcrumbGroup: MiniStack › EC2 › Instances│
│ SideNav      ├──────────────────────────────────────────────┤
│  Compute     │                                              │
│   • EC2      │  Main content (service home / list / detail) │
│   • Lambda   │                                              │
│  Storage     │                                              │
│   • S3       │                                              │
│  Database    │                                              │
│   • DynamoDB │                                              │
│  Messaging   │                                              │
│   • SQS      │                                              │
│  …           │                                              │
│              │                                              │
└──────────────┴──────────────────────────────────────────────┘
   280px wide                          fluid (min 720px)
   collapsible
```

**Cloudscape components used in Phase 1 (locked inventory):**

| Component | Purpose | Phase 1 surface |
|-----------|---------|-----------------|
| `AppLayout` | Three-region shell (header offset, sidebar, content, optional tools) | Root of every route |
| `TopNavigation` | Top bar with brand, search, region indicator | Shell header slot |
| `SideNavigation` | Left sidebar with grouped service links | Shell `navigation` slot |
| `BreadcrumbGroup` | Breadcrumb trail derived from current route | First child of `content` slot |
| `Autosuggest` | Typeahead service search (NAV-01, D-05) | Embedded in `TopNavigation.utilities` |
| `ContentLayout` | Page header + body wrapper inside main content | Content slot wrapper |
| `Header` | Page title with description and actions | Inside `ContentLayout.header` |
| `Container` | Card wrapper for service-home summary blocks (NAV-04) | Service home page |
| `KeyValuePairs` | Resource count + status summary on service home | Service home page |
| `StatusIndicator` | "running / stopped / error" pill (used here only for service-level health rollups) | Service home page |
| `Spinner` | Global route-loading state for `React.lazy` Suspense fallback | `<Suspense>` boundary |
| `Alert` | Inline error display when the Console API or AWS API call fails | Service home, error boundary |
| `Box` | Empty state composition primitive | Service home with zero resources |
| `Link` (internal `react-router` `<Link>` wrapped) | Navigation between routes | Sidebar, breadcrumbs, search results |

**Out of scope for Phase 1** (do not implement, even if Cloudscape offers them): `Table`, `CollectionPreferences`, `PropertyFilter`, `Pagination`, `Form`, `Modal`, `Wizard`, `S3ResourceSelector`, `Tabs`, `Cards`, `SplitPanel`, `HelpPanel`, `Toggle` for dark mode. These belong to Phase 2-5.

## Spacing Scale

Cloudscape exposes spacing tokens via `@cloudscape-design/design-tokens`. **Always reference tokens, never write px literals in components.** All Cloudscape tokens are multiples of 4 by design.

| Token (CSS var) | JS export | Value | Usage in Phase 1 |
|-----------------|-----------|-------|-------------------|
| `--awsui-space-scaled-xxxs` | `spaceScaledXxxs` | 2px | (Cloudscape internal — do not use directly) |
| `--awsui-space-scaled-xxs` | `spaceScaledXxs` | 4px | Icon-to-label gap inside sidebar links |
| `--awsui-space-scaled-xs` | `spaceScaledXs` | 8px | Compact element spacing (badge padding, breadcrumb separators) |
| `--awsui-space-scaled-s` | `spaceScaledS` | 12px | Inline form gap (not used Phase 1) |
| `--awsui-space-scaled-m` | `spaceScaledM` | 16px | Default content padding inside Container |
| `--awsui-space-scaled-l` | `spaceScaledL` | 20px | Header-to-body gap inside ContentLayout |
| `--awsui-space-scaled-xl` | `spaceScaledXl` | 24px | Section gap on service home page |
| `--awsui-space-scaled-xxl` | `spaceScaledXxl` | 32px | Major section breaks |
| `--awsui-space-scaled-xxxl` | `spaceScaledXxxl` | 40px | Page-level vertical rhythm |

**Layout token (fixed regions):**

| Token | Value | Usage |
|-------|-------|-------|
| TopNavigation height | 56px (Cloudscape fixed) | Header offset for AppLayout |
| Sidebar default width | 280px (Cloudscape fixed) | `AppLayout.navigationWidth` (do not override in Phase 1) |
| Main content min width | 720px | Below this, sidebar auto-collapses (Cloudscape behaviour) |
| Main content max width | none — fluid | Desktop-first per NAV-05 |

**Exceptions:** none. Phase 1 never hardcodes a px value. If a Cloudscape component does not expose a slot for the gap you need, the answer is "use the next-larger token," not a custom value.

## Typography

Cloudscape ships a typographic scale tuned for AWS Console. Phase 1 uses exactly four roles, all sourced from `@cloudscape-design/design-tokens`. Font weight is restricted to two values (400 regular, 700 bold) to honor the GSD typography rule.

| Role | Token | Size | Weight | Line height | Usage in Phase 1 |
|------|-------|------|--------|-------------|------------------|
| Body | `--awsui-font-size-body-m` | 14px | 400 | 22px (1.57) | Sidebar links, breadcrumbs, body copy, KeyValuePairs values |
| Label | `--awsui-font-size-body-s` | 12px | 700 | 16px (1.33) | KeyValuePairs labels, sidebar section group titles, status pill labels |
| Heading | `--awsui-font-size-heading-m` | 18px | 700 | 22px (1.22) | Service home page Header (`<Header variant="h2">`) |
| Display | `--awsui-font-size-heading-xl` | 24px | 700 | 30px (1.25) | Top-level page Header (`<Header variant="h1">`) — used only on the console root `/` landing page |

**Font family (locked):** `"Open Sans", "Helvetica Neue", Roboto, Arial, sans-serif` (Cloudscape default). Loaded by `@cloudscape-design/global-styles` — do not import a separate font.

**Forbidden in Phase 1:**
- More than 4 sizes
- More than 2 weights (no `font-weight: 500` / `600`)
- Custom font families
- `font-size` literal values in components — always use the Cloudscape token or, preferably, a Cloudscape `<Header>` / `<Box variant="...">` component that applies the token internally

## Color

Cloudscape's light theme uses a near-white surface palette with AWS-blue accents. Phase 1 honors the 60/30/10 GSD rule by mapping it onto Cloudscape's semantic tokens. **All color values come from `@cloudscape-design/design-tokens`** — never write hex literals in components.

| Role | Cloudscape token | Value (light theme) | Usage in Phase 1 |
|------|------------------|---------------------|-------------------|
| Dominant (60%) | `--awsui-color-background-layout-main` | `#f2f3f3` (warm-grey-1) | Main content background, the canvas behind every page |
| Secondary (30%) | `--awsui-color-background-container-content` | `#ffffff` (white) | Containers, cards, KeyValuePairs surfaces, sidebar background |
| Secondary (30%) | `--awsui-color-background-layout-panel-content` | `#fafafa` (warm-grey-0) | TopNavigation background, BreadcrumbGroup strip |
| Accent (10%) | `--awsui-color-text-accent` | `#0972d3` (AWS blue) | See "Accent reserved for" below |
| Destructive | `--awsui-color-text-status-error` | `#d91515` (AWS red) | Inline `<Alert type="error">` text and the destructive `Button` variant (Phase 1 uses none, but the token is reserved) |
| Success rollup | `--awsui-color-text-status-success` | `#037f0c` (AWS green) | `<StatusIndicator type="success">` on service home rollups (e.g., "all instances healthy") |
| Warning rollup | `--awsui-color-text-status-warning` | `#8d6605` (AWS amber) | `<StatusIndicator type="warning">` on partial-health rollups |

**Accent reserved for (explicit list — never "all interactive elements"):**

1. The active sidebar link (selected state — Cloudscape `SideNavigation` applies this automatically)
2. Hyperlinks inside body copy (Cloudscape `<Link>` default)
3. The brand wordmark "MiniStack" in the TopNavigation
4. Focus rings on keyboard-focused interactive elements (accessibility, Cloudscape default)
5. The Autosuggest selected-option highlight in service search

**Accent is NOT used for:**
- Sidebar link icons (use `--awsui-color-text-body-default`)
- Breadcrumb separators or non-active breadcrumb items (use `--awsui-color-text-body-secondary`)
- Container borders (use `--awsui-color-border-divider-default`)
- TopNavigation background
- Buttons in Phase 1 (Phase 1 has no primary action buttons — there is nothing to create yet)

**Forbidden in Phase 1:**
- Hex literals anywhere in `web/src/`
- Tailwind classes (Tailwind is not installed)
- Custom CSS files except `web/src/styles/tokens.css` which only re-exports Cloudscape tokens if needed
- Dark-mode tokens (`@cloudscape-design/global-styles/dark-mode`) — Phase 5 only

## Service Categories (locked navigation taxonomy)

Per CONTEXT.md D-04, services are grouped under the AWS Console categories. Phase 1 ships the navigation taxonomy below; service items inside each category are populated from `SERVICE_HANDLERS` keys via the `/_console/api/services` registry endpoint. Only categories with at least one active service are rendered.

| Category | Display order | Phase 1 service items (initial seed) |
|----------|---------------|---------------------------------------|
| Compute | 1 | EC2, Lambda |
| Storage | 2 | S3 |
| Database | 3 | DynamoDB |
| Networking & Content Delivery | 4 | (EC2 sub-resources surface here in Phase 2 — Phase 1 leaves the group empty if no active service) |
| Application Integration | 5 | SQS, SNS |
| Management & Governance | 6 | CloudWatch, IAM |
| Security, Identity & Compliance | 7 | KMS, Secrets Manager |
| Other | 99 | Catch-all for any registered service whose category is unknown |

**Sidebar grouping rules:**
- Use Cloudscape `SideNavigation` `type: "section"` headers for categories
- Empty categories are hidden, not rendered as empty sections
- Service items are sorted alphabetically within a category
- Category headers use the Label typography role (12px / 700)

## Routing Contract

Per CONTEXT.md D-11 (Claude's discretion), the recommended URL pattern is **history-based (BrowserRouter)** with the ASGI SPA fallback handler:

| Route | Component | Purpose |
|-------|-----------|---------|
| `/_console/` | `ConsoleHome` | Landing page — grid of category cards with service counts |
| `/_console/services/:serviceKey` | `ServiceHome` | Service home page — resource count + status summary (NAV-04) |
| `/_console/services/:serviceKey/*` | `ServiceHome` (Phase 1 stub) | Phase 1 renders the service home for any sub-path; Phase 2+ replaces this with real CRUD routes |
| `/_console/*` (no match) | `NotFoundPage` | 404 inside the shell — "We could not find that page" + link back to `/_console/` |

**ASGI fallback rule** (Pitfall 7 mitigation): any GET request matching `/_console/*` that does not resolve to a static asset must return `index.html` with `Cache-Control: no-cache`. Static asset bundles (JS/CSS/woff2) get `Cache-Control: max-age=31536000, immutable`.

**Primary CTA for Phase 1:** none. Phase 1 has no create/destructive actions — the only "action" is navigating between services. The primary affordance is the service search Autosuggest, not a `<Button variant="primary">`.

**Tone rules:**
- Imperative voice for instructions ("Create resources via…", not "You can create…")
- No exclamation marks
- No emoji in copy
- Service display names match the AWS canonical capitalization (`EC2`, `S3`, `DynamoDB`, `Lambda`, `SQS`)

## Interaction Contract

| Interaction | Behavior | Cloudscape mechanism |
|-------------|----------|----------------------|
| Click sidebar service link | Navigate to `/_console/services/{key}`, mark link active, update breadcrumb | `SideNavigation` `onFollow` → React Router navigate |
| Click breadcrumb item | Navigate to that level | `BreadcrumbGroup` `onFollow` → React Router navigate |
| Type in service search | Filter `services` list by name (case-insensitive substring) — typeahead per D-05 | `Autosuggest` controlled component |
| Select search result | Navigate to that service home page | `Autosuggest` `onSelect` |
| Toggle sidebar collapse | Hide/show sidebar; persist preference in `localStorage` under `ministack:console:sidebarOpen` | `AppLayout` `onNavigationChange` |
| Resize below 720px main width | Sidebar auto-collapses to icon-only mode | Cloudscape `AppLayout` default behaviour |
| Service home loads | Show `<Spinner>` while React Query is fetching, then render KeyValuePairs | `<Suspense>` + `useQuery` `isLoading` |
| Service home fails to load | Render `<Alert type="error">` with retry button | TanStack Query `error` state + `refetch()` |
| Click "Retry" on error alert | Re-run the failed query | `refetch()` |
| Manual refresh | NOT in Phase 1 (Phase 2 / CRUD-06). Phase 1 relies on React Query default `refetchOnWindowFocus` | n/a |
| Keyboard: `/` | Focus service search | Custom hotkey (Phase 1 nice-to-have, plan can defer) |
| Keyboard: `Esc` in search | Clear and blur search | `Autosuggest` default |

## Accessibility Contract

Cloudscape components are WCAG 2.1 AA compliant out of the box. Phase 1 must not break this:

- Every `<Icon>` used as a button must have `ariaLabel`
- All routes must update `document.title` to `MiniStack — {pageName}`
- Focus order: TopNavigation → Sidebar → Main content → Footer (Cloudscape `AppLayout` enforces this)
- Color contrast: do not override Cloudscape token colors; light theme already meets AA
- Keyboard: every interactive element reachable via Tab; sidebar items navigable via arrow keys (Cloudscape default)
- Reduced motion: rely on Cloudscape's built-in `prefers-reduced-motion` handling
